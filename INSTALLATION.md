# Local synthetic installation

Tested: Windows, PHP 8.5.12 (x64 NTS) with PDO MySQL, MySQL 8.0.45/InnoDB. Required PHP facilities include sessions, filter, PCRE, hash, JSON and password/random functions. The source uses PHP 8 features; other versions/platforms and MariaDB were not verified by this run. No Composer, Node, Python, image generation or CDN dependencies are needed to serve the prepared files.

1. Use a disposable local MySQL instance and a fresh schema. schema.synthetic.sql contains CREATE DATABASE IF NOT EXISTS chisel and USE chisel: confirm that no existing chisel database or personal data is present before importing it. Do not point this setup at an existing coursework/production instance. Import only schema.synthetic.sql through your local MySQL client. It creates users, admin, products and cart with constraints and three synthetic products; it contains no account credentials or real dump data.
2. Create a dedicated local application database account with only SELECT, INSERT, UPDATE and DELETE on chisel.*. Choose a fresh private password. Schema administration should use a separate setup account; do not run the application as root.
3. Set DB_HOST, DB_PORT, DB_NAME, DB_USER and DB_PASSWORD in the PHP process environment, as described by .env.example. PHP does not read that file itself. Keep secrets out of source control, command transcripts and public evidence. Defaults are loopback, port 3306 and schema chisel; DB_USER and DB_PASSWORD are mandatory. The earlier isolated test used port 33161; that test port is not a required application setting.
4. Use a private writable PHP session directory and private error log outside the served directory, and disable display_errors. For a local development session, start PHP bound only to loopback from the repository directory: `php -S 127.0.0.1:8088 -t .`. Do not expose the development server publicly. Stop it with Ctrl+C. Installation instructions are not an executed setup during candidate preparation.
5. Open index.html for the coursework landing page or shop.php for the database catalogue. Register only fictional test identities through register.php and sign in through login.php. No working contact delivery, checkout or payment endpoint is provided.
6. Administrator access uses admin_login.php and the admin table. No administrator is seeded. If testing admin workflows, privately generate a password hash with PHP password_hash using PASSWORD_DEFAULT and insert a chosen synthetic login and that hash into admin(admin,password) using your local setup client. Do not use a plaintext password, publish its hash or import original accounts. The HTTP test evidence used disposable identities provisioned by a private harness; that harness and its secrets are intentionally excluded.

## Limits

Cart stock checks are not inventory reservation or checkout transactions. Production hosting, TLS, comprehensive rate limiting, security monitoring, accessibility and broad concurrency behavior require separate work. Real records, browser sessions, server logs, .env and database exports must remain private. No remote deployment instructions or automatic destructive cleanup command is provided. Dispose only your own identified test instance/data when finished.
